# E2E-051-a-shadowing-twin-needs-no-second-argument: the soft twin points instead of restating

A `deferred` hard entry silences the hard finding and leaves the soft one
standing (§FS-003-exceptions.3), so the file only goes quiet once a soft entry
sits beside it. That twin holds no judgment of its own — what to accept, why,
and what retires it were all decided in the hard registry — yet before
`--shadows-hard` it had to restate a `reason` and an `until` it did not own
(§FS-003-exceptions.2.3).

This case runs the one-flag form. The written entry carries the pointer, the
`kind` copied from the entry it shadows, and a `max_accepted` of its own; it
carries neither `reason` nor `until` (§FS-005-exception-add.1.1,
§FS-005-exception-add.3).

The ceiling is worth reading twice: 100 lines is far above rule `rust`'s hard
limit of 4. A soft ceiling there is normally refused as one that could never
fire, and it is accepted here only because a *deferred* hard twin keeps the
soft finding alive above the limit (§FS-005-exception-add.4) — which a
shadowing entry has by construction.
